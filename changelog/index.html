Changelog¶

Rhema follows semantic versioning: the language's syntax, the builtin functions' names and arguments, and the rhema command's options are the public interface. A breaking change raises the major version; a deprecation is announced one version before the removal.

Unreleased¶

  • VS Code extension in editors/vscode: highlighting, problems from rhema check as you type, Run and Compile commands, folding and snippets for .rhm files. Its tests check the grammar against the compiler's keywords and every .rhm file in the repository (CI job editor), and drive the extension in VS Code against a real rhema. Published on the Visual Studio Marketplace as rhema.rhema-language (0.1.0, preview).
  • Fixed: a problem with a name, a child reference or a call was reported at the start of the equation or declaration holding it, so value = foo gave the column of value for "unknown name 'foo'". Every such message now points at the name itself. The parser records where each one is written (At in rhema_ast.ml); generation is unchanged.
  • Six new question types, all built answer first: counting.rhm (arrangements, selections and probabilities, with named questions counting and probability), number_theory.rhm, series.rhm, limits.rhm, eigen.rhm and inequality.rhm. Each has a test that checks its answers independently.
  • Builtins: factorial, choose, permutations, gcd, lcm, pow_mod and mod_inverse on whole numbers (rhema_integers.ml, with overflow checks); number_latex, a number in LaTeX with fractions as \frac; and the rays set_above and set_below, rendered (a, \infty) and (-infinity, a]. A union of sets is written A U B in PG without brackets around its parts.
  • A leaf (a generator, a literal or a terminal) may be read as $n.value without a synth value declaration; anything else on a leaf is refused with a hint to write str($n.value).
  • Fixed: a polynomial with a negative leading term was printed as a difference, 9 - (5 \cdot x^{2} + 4 \cdot x); it is now -5 \cdot x^{2} + 4 \cdot x + 9.
  • Documentation site (docs/, mkdocs.yml): a home page, an eight-chapter tutorial, the language reference with its grammar in EBNF, the command, the builtin functions (generated from rhema doc), the library and difficulty budgets. Every example file is checked and run in CI, and the site must build without warnings.
  • Fixed: distinct in a set counted two different named questions built on the same rule as repeats, and could confuse rules of two files at the same line; it now compares the question type and the rule's file too.
  • rhema doc groups functions by value type (matrix2 with the matrices, differentiate with the formulas, the generators on their own) and points to the website. The set listing no longer prints an empty budget list.
  • CI: GitHub Actions builds the package from a clean export on OCaml 4.14 and 5, Linux and macOS, exactly as opam does, installs it into a prefix and runs the command; a second job builds the whole tree with every suite, the documentation examples and site, and the Python checks.

0.1.1 (2026-10-25)¶

Packaging only. The classic generator and its PG parser, which need pprint and menhirCST, are built in the development profile only, so the package's tests no longer fail on a machine without them (dune build -p rhema @runtest). No change to the language or the command.

0.1.0 (2026-10-24)¶

The first version with a name.

  • Language: Rhema, files .rhm. Attribute grammars with inherited budgets and synthesized attributes; include; import "file.rhm" as name with arguments at the boundary; question NAME { ... } blocks; set NAME { ... } declarations with budgets drawn fixed, from a list, or around a mean; pg_context / pg_width per question; {answer ...} blanks.
  • Values: Number, Formula, Polynomial, Equation, Boolean, Matrix, Set, Vector, Complex, with their builtin functions (rhema doc).
  • Difficulty: every library grammar spends a cost budget exactly; --set cost=N; sets fix the mean of a part.
  • Command: rhema FILE.rhm [-o OUT.pg], check, run, list, doc; GNU error format and exit codes; -I and RHEMA_PATH; one assignment is one paper, --student for a student's own.
  • Library: 24 question grammars, 2 grammar libraries, 1 example set file, installed to share/rhema by dune install.
  • Layout: generator/rhema/{lib,bin,test}, generator/stdlib, generator/grammars for the user's own files.
  • Packaging: opam metadata in generator/dune-project (generated rhema.opam, MIT, tests run with --with-test); RELEASING.md describes tagging, the source archive and the opam-repository entry.
